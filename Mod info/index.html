CP26 - Technical Documentation

Reference documentation for Community Patch 2026 (CP26), a community overhaul for Star Trek: Infinite. Written for contributors: what CP26 changes, how, and where.

1. Overview

CP26 is a community overhaul for Star Trek: Infinite (1.0.7). It works through two distinct Paradox modding mechanisms:

Full replacement (replace_path)

43 vanilla files are entirely replaced by a modified CP26 copy (declared in descriptor.mod). The original vanilla file is completely ignored, so CP26 must reproduce all of its useful content in addition to its own changes.

Pure addition

Everything else (hundreds of files) is simply added on top of normal game loading: new events, species, quests, megastructures, and so on. Paradox automatically loads every recognized .txt/.gfx/.asset file in the standard folders - no need to declare them in descriptor.mod.

Naming conventions

Understanding file prefixes is the key to navigating the mod:

PrefixMeaning
hornblower_*Files from the base "Hornblower" mod (the foundation CP26 is built on) - appear in replace_path when modified
aa_*"Ambient/AI" - non-player-startable AI major powers (Ferengi, Gorn, Orion, Tholian) and their subsystems (government, civics, personalities, system init)
cp26_*CP26-original narrative/systemic content (quest arcs, megastructures, special projects)
zz_cp26_*CP26 patches, fine-tuning, or late additions - often bugfixes for vanilla/Hornblower content or balance tweaks
zz_mm_*Megastructures ported from a third-party "Mid-game Megastructures" mod (Dyson Swarm, Fusion Hub, Lifter)
00_*, 01_*, 02_*...Numeric prefix = Paradox load order (files load alphabetically within a folder)

The "stub + split" pattern

Several large vanilla files declared under replace_path have been reduced to a one-line comment (e.g. common/quest_tree_nodes/00_ufop_nodes.txt, common/solar_system_initializers/hornblower_initializers.txt, events/hornblower_game_start.txt). Their real content was split into dozens of individual files in the same folder (e.g. qt_ufop_a1.txt, game_start_101.txt). Paradox automatically loads every .txt in a folder, so this split works without any extra declaration - and lets new nodes/events be added without ever touching the replaced file.

For future modders: if you're looking for a UFOP quest node or a game_start event, don't search 00_ufop_nodes.txt or hornblower_game_start.txt - they're empty. Look for the matching qt_ufop_<name>.txt or game_start_<id>.txt file instead.

2. Replaced vanilla files (43 replace_path entries)

Every entry below comes from an actual diff between the CP26 file and its counterpart in the vanilla Steam install - not from reading the changelog.

Ship components

common/component_templates/00_hornblower_utilities_roles.txt balance

  • Officer upkeep cost of combat computers: -10 → 0 (no more officer upkeep).
  • size_restriction lists heavily expanded to include CP26's new hulls (Sovereign, Voyager, Ambassador, Constellation, Lantree, K'vort, Kamarag, Jach, Raptor, Praetor, Ferengi cruiser/battleship/titan, Gorn/Orion/Tholian).
  • ai_weight raised from 3 to 4 on several templates (stronger AI preference).

common/component_templates/00_hornblower_weapons_missiles.txt balance

  • Medium/large photon torpedoes (tier 2): alloy cost raised from tier-3 to tier-5, and a new tetryon cost added (now requires a strategic resource).

Country types

common/country_types/00_country_types.txt AI/balance

  • Merges the former zz_cp26_default_country_type.txt; adds ignores_warp_range = yes to the default type and about 20 mobile country types (paired with OUTPOST_WARP_RANGE_RADIUS = 0 in the defines - outposts no longer grant a warp-range bubble).
  • min_navy_for_wars: 0.01 → 0.14 (the AI waits for a larger navy fraction before declaring war).
  • New dynamic support-fleet scaling system (constructors/science ships/colonizers) driven by cp26_empire_size_small/medium/large/huge flags, set yearly by an AI pulse based on planet count - replaces vanilla's static bounds.
  • Base support-fleet counts roughly halved (e.g. 50→35, 100→55), offset by the new dynamic scaling.

common/country_types/03_country_types_megacorp.txt - minor addition of the same ignores_warp_range flag.

Diplomacy

common/diplomatic_actions/00_actions.txt & 00_hornblower_actions.txt new system

  • Systematic widening of triggers to include CP26's new country types: is_country_type = contender / is_ferengi_empire / is_gorn_hegemony / is_orion_syndicate - these empires can now use standard diplomatic actions previously gated to the default type only.
  • A Ferengi-specific branch is added to an intel-sharing action (100 intel, open borders for 3600 days, survey of owned + subject planets).
  • Vassalization fully rewritten: the vanilla action_start_puppet_state_process action (requiring an envoy) is replaced by a CP26 system with no envoy requirement, custom tooltips (CP26_VASSALIZATION_PENDING), AI gating (cooldown, relative power, planet count, no federation/defensive pact/guarantee, no recent target, 50+ trust), cp26_vassalization_pending_actor/target flags, fires country_event = cp26_vassalization.1, 3-year AI cooldown after an offer.
  • New action action_cp26_offer_war_goal_peace: a wartime negotiated-peace proposal (cp26_vassalization.6).
  • action_support_independence, action_break_support, action_release_subject, action_liberate_subject, action_request_subject_liberation moved here and rewritten to work on is_regular_empire subjects, not just vanilla's minor/occupied ones.

common/game_rules/00_rules.txt

Technology & unlock system

Every tech has an area (physics/society/engineering), a tier (0-5), and a category. Costs and base weights reuse vanilla's tiered scripted variables (@tier1cost1...@tier5cost3), except hull-unlock techs, which all use a single shared variable, @specialhullweight, instead of the generic tier weight.

Faction gating uses potential (removes the tech from the tree entirely if false, not just greyed out), checked against scripted triggers defined in common/scripted_triggers/z_aa_scripted_triggers.txt:

is_ferengi_empire = { OR = { is_country_type = ferengi_alliance  has_country_flag = ferengi  has_country_id = "ferengi" } }
is_gorn_hegemony  = { OR = { is_country_type = gorn_hegemony  has_country_flag = gorn_hegemony  has_country_flag = gorn  has_country_id = "gorn" } }
is_orion_syndicate= { OR = { is_country_type = orion_syndicate  has_country_flag = orion_syndicate  has_country_flag = orion  has_country_id = "orion" } }

is_ufop/is_klingon/is_romulan/is_cardassian are the equivalent Hornblower-provided triggers. No is_tholian trigger exists - Tholians are gated purely at the ship_sizes level (potential_country = { has_country_id = tholian }), not from the tech side, which is why they have no bespoke hull techs (see the faction table below).

AI timing: hull techs use a weight_modifier keyed on years_passed (factor 0 before a gate year, ramping up after) plus a separate ai_weight multiplier for AI empires only. This is the mechanism behind the AI hull-unlock speedup already noted in §2 (the generic chain's windows were compressed to roughly a quarter of vanilla's span).

One tech, several faction skins (triggered_config): the 5-tier generic hull chain - tech_corvette_unlock, tech_destroyer_unlock, tech_cruiser_unlock, tech_battleship_unlock, tech_titan_unlock - is a single tech ID per tier with no potential restriction, carrying one triggered_config block per faction that swaps only the title/desc/icon shown to that faction. Researching "Cruiser Development" shows Excelsior to a UFOP player and K'tinga to a Klingon player - same tech, same prerequisites, same research cost, different ship at the end.

Bespoke vs. shared: factions with their own multi-step hull chain (UFOP, Klingon, Gorn, Orion, Romulan) get faction-specific weight_modifier pacing, hull-to-hull prerequisites (a faction's late hull requires its own earlier hull, not just the generic tier), and quest-flag gates - none of which is possible on a single shared tech with only cosmetic icon swaps. Cardassian and Ferengi have no bespoke hull file and rely entirely on the shared chain's per-faction skin.

Hidden/quest-granted techs: tech_lamarr_unlock, tech_odyssey_unlock and tech_defiant are weight_modifier = { factor = 0 } (never naturally rolled) and are instead granted directly via give_technology from quest-tree nodes (qt_ufop_upgrade_voyager_lamarr.txt, qt_ufop_upgrade_enterprise_odyssey.txt, qt_ufop_b7.txt) - hidden = yes caused issues so weight = 0 is used as the workaround instead.

Duplicate-technology avoidance: tech_warp_speed_increase_1 and _2 were removed from their original vanilla/Hornblower files with a comment explaining they're redefined in zz_cp26_warp_techs.txt to avoid a "Duplicate technology" engine error (a new tech_warp_speed_increase_3 was added alongside them). This is the only place in common/technology/ where a tech is deliberately relocated to sidestep this error.

9. Balance decisions

  • Military fleet cap (~36 line ships): cp26_under_reduced_fleet_military_cap caps empire-wide line hulls at 36 (common/scripted_triggers/aa_scripted_triggers.txt) so fights stay at a readable, roughly "3 fleets of 12" scale instead of vanilla's late-game blob stacks. The complementary per-fleet COMMAND_LIMIT tuning (base 24 / max 96) is written but currently disabled in common/defines/zz_cp26_reduced_fleet_scale_defines.txt pending a performance check - only the 36-hull empire cap is live.
  • Command-limit tech ladder shortened (4 tiers → 2): with the fleet cap in place, the old +15/+25/+35/+45 ladder let empires field far more ships than the cap allows. Trimmed to +10/+15 from tech, with the difference moved into per-planet military buildings (Stronghold +4, Fortress +8) so command limit scales with territory rather than research alone.
  • Torpedo tier and tetryon cost: photon torpedoes moved from tier-3 to tier-5 alloy cost plus a new tetryon requirement, so late-game weapon upgrades compete for the same strategic resources as shields/reactors instead of being a free alloy sink.
  • AI start resource buffs (Klingon/Cardassian/Ferengi only): vanilla's AI budget code won't build outposts below 75 influence or colony ships below 2000 stored food, thresholds these three starts didn't reach for many in-game years. Fixed with AI-only starting injections (events/zz_cp26_major_start_balance.txt, cp26_start_balance.1): Klingon +150 alloys/+50 influence, Cardassian +200 alloys/+75 influence, Ferengi +200 alloys. UFOP, Romulan, Tholian, Gorn and Orion starts were left untouched - their budgets already clear the thresholds.
  • Warp speed curve: base interstellar travel speed cut about 35% (WARP_INTERSTELLAR_TRAVEL_SPEED 0.1 → 0.065) to make the galaxy feel larger early game, recovered progressively through 3 warp-speed techs up to 120% of vanilla by "Warp 7" - a deliberate slow-start, fast-finish curve rather than a flat nerf.
  • Hero ship hit points halved: Voyager (7000 → 2500 HP) and the D'deridex hero ship (10000 → 4500 HP) were effectively unkillable once combined with their already-high vanilla disengage chance (1.50 / 1.20) - both values were tuned down, the disengage chance left as-is.
  • Battleship fleet-slot size corrected: Tholian, Orion and Gorn battleships shipped with size_multiplier = 8 but only fleet_slot_size = 3 against the vanilla standard of 4 for that power level - a roughly 33% hidden fleet-cap advantage. Corrected to 4 across all three.
  • Minor faction civics trimmed, not redesigned: Infinite's civics are all upside with no built-in downside, so oversized minor-faction civics (e.g. Tholian isolationism stability bonus 10 → 5, Gorn predatory war exhaustion reduction -30% → -25%) were scaled down numerically rather than given new maluses, keeping them stronger than major-empire civics without being absurd.

Expansion Pressure (escalating outpost cost) not yet playtested

This optional campaign setting is disabled by default. When enabled in the start-of-game setup, building a new starbase becomes progressively more expensive in Influence and construction resources, the more starbases a country already owns. It applies identically to the player and to AI empires (default and CP26's contender type), and stacks on top of Infinite's distance-based Influence expansion cost (NEconomy.EXPANSION_COST_*) and Empire Size/Admin Cap overextension penalty (empire_size_over_cap).

Counted via Infinite's dedicated count_owned_starbase trigger - any starbase level, not just un-upgraded outposts. While the setting is enabled, cp26_expansion_pressure.1 recalculates each country's tier after every completed outpost, yearly, and immediately when the option is enabled.

The first starbase is free of any malus. Bands are non-linear to keep the effect readable while making expansion pressure visible from the second completed outpost. On Infinite's base cost range (70-150 Influence before modifiers), Tier 4 works out to roughly 200-420 Influence per new outpost.

AI budget fix (all difficulties): vanilla's common/ai_budget/00_influence_budget.txt hardcodes how much Influence the AI reserves before attempting to expand at static_min = 75 / static_max = 150 - matching vanilla's un-modified EXPANSION_COST_BASE/EXPANSION_COST_MAX (70/150). Left alone, the AI would under-reserve once real costs climb past Tier 1-2 and stall/behave erratically. Rura Penthe

CP26's blanket rewrite of hornblower_initializers.txt had dropped the vanilla Rura Penthe initializer entirely. Sol Nova system

The bespoke "Suliban" system was replaced with a static "Sol Nova" system containing an uncolonized "Terra Nova" planet (common/solar_system_initializers/cp26_sol_nova_initializer.txt), and the old dynamic on-game-start Terra Nova spawn script was disabled to stop a duplicate-planet bug it caused.

Galaxy radius

Known risk area, not fully resolved. The Stellaris engine renders the galaxy inside a fixed ±500-unit box; exceeding it in scenario files has caused SIGSEGV crashes during earlier development (chased through radius values 900→460→500→570→650 before settling back at 500). map/setup_scenarios/Alpha-Beta_medium.txt currently ships with radius = 800, set in a later commit without revisiting the original constraint. This is either evidence the 500 limit was overly conservative, or a latent crash risk - worth checking before further map changes.

Adding a new major/regional empire ("contender" archetype)

Full recipe: species class, graphical culture, authority, civics (with potential = { always = no } so they can't be picked by the player), 3 ship sizes, section/component templates, global ship designs, .asset files, a solar system initializer, an on_game_start event, an on_actions hook, 2 scenario-file entries, ship-fraction edits in the contender country type, and EN/FR localisation.

Two traps worth knowing before starting:

  • late_init_effect in a system initializer is not reliably called for contender-type empires spawned via setup_scenarios - capital setup must happen in an on_game_start event instead, or the empire ends up with a country and species but no owned capital.
  • Never call create_ship_design/add_ship_design inside a system initializer - it can silently abort late_init_effect partway through (this is how the Ferengi's second starting ship went missing during development).

Use type = contender for a rival AI empire with normal visibility, or a dedicated country type (as Ferengi has, ferengi_alliance) when you need observable = no / show_in_contacts_list = no for a hidden-until-first-contact empire.

Minor species classes & traits

The ~19 minor peoples share 3 cosmetic-only species classes with no mechanical effect: HRB_DIPLO (Bajoran, Betazoid, Trill, Kaelon, Malcorian, Iyaaran), HRB_TRADE (Bolian, Boslic, Hupyrian, Lissepian, Pelian, Farian), HRB_HARDY (Acamarian, Cairn, Talarian, Tanugan, Kesprytt, Ktarian, Idanian). Separately, all 20 minors have their own 3-trait set (60 traits total, common/traits/zz_cp26_minor_species_traits.txt) for actual gameplay differentiation.

11. Notable bugfixes with lasting design impact

  • AI capital shipyard: AI empires could start without a functional capital shipyard, an asymmetry against the player. Fixed by cp26_ai_shipyard.1 (common/on_actions/zz_cp26_on_game_start.txt), which force-builds a capital starport and shipyard module for AI-controlled major/minor/contender countries.
  • Construction-queue crash: create_colony immediately followed by removing the colony shelter and adding the capital building in the same tick corrupted the engine's save-game construction queue. Fixed by dropping the same-tick shelter removal entirely across all affected colony scripts (Luna, Mars, Tholia, Orion, Gorn, Denobula, Glintara).
  • Borg crisis "The Freed" chain: vanilla ships the Borg crisis final chain and the 3 Voyager special-project events (PROBE_DEFENSES, COUNTERACT_MEASURES, DELIVERANCE) with their event_chain reference commented out, so the situation log never resolved. Uncommented and wired to borg_crisis_end / borg_crisis_end_the_freed.
  • UFOP first-contact bonus event (country.27500): used the invalid root.from scope, silently failing or applying the opinion bonus to the wrong country. Fixed to who = from with same-value guards against double-processing.
  • Minor-empire mission dead ends: several mission.* events gated every option behind is_ufop/klingon/romulan/cardassian, leaving AI minors (Bajoran, Farian, etc.) with zero valid choices and a stuck event. Added a fallback option for empires matching none of the four majors.

13. Testing with the debug console

A step-by-step guide to testing CP26's story arcs without playing through them naturally - written for someone who has never opened a Stellaris/Infinite console before.

Opening the console

  1. Start a normal game (not Ironman - Ironman disables the console entirely).
  2. Press the key below your Esc key, next to 1 (usually `/~ on a US keyboard, § or ² on some European layouts) to open the console box at the bottom of the screen.
  3. Type a command and press Enter. The console stays open - keep typing more commands.
  4. Save your game before testing anything destructive; console commands can desync multiplayer and occasionally corrupt a save if used carelessly (always test on a save copy, not your main campaign).

General-purpose commands (vanilla, not CP26-specific)

CommandWhat it does
event <event_id>Fires a country_event immediately on your currently played country. This is the main tool for testing CP26's story events - see the arc tables below for real IDs.
effect <effect>Runs a raw scripted effect, e.g. effect add_country_flag = my_flag or effect remove_global_flag = my_flag. Used to set/clear the flags that gate CP26's arcs.
play <country_id>Switches which empire you're playing/controlling - lets you test the same arc's reaction from every major power without restarting.
debugtooltipToggles an overlay that shows internal IDs (country ID, planet ID, fleet ID...) when you hover things on the map - use it to find the <country_id> for the play command above.
research_technology <tech_id>Instantly completes and grants a specific technology.
add_research_option <tech_id>Adds a tech to your research pool without granting it (so you still have to research it normally).
research_all_technologiesGrants every researchable technology - useful to jump straight to late-game hulls.
instant_buildToggles instant construction/production - buildings, ships and megastructures complete immediately.

event only works on country_events. A planet_event can't be called with event directly - it needs to be wrapped in an effect that finds the planet first, e.g. effect = { random_galaxy_planet = { limit = { has_planet_flag = planet_mars } planet_event = { id = cp26_a500.1 } } } (see the Mars arc table below for a working example).

14. For future contributors

  • Never edit a vanilla file directly in the game folder - every change must go through a CP26 file, either via replace_path (the whole file is replaced, declared in descriptor.mod) or as a standalone additive file.
  • Before searching a "root" file (00_ufop_nodes.txt, hornblower_initializers.txt, hornblower_game_start.txt), check whether it's been reduced to a stub - see the stub+split pattern in §1.
  • Follow the existing naming prefixes (§1) to stay consistent: cp26_* for new narrative content, zz_cp26_* for late patches/tuning.
  • CHANGELOG.md is behind - if you update it, verify the actual code state first (as this page did) rather than trusting the latest entries.
  • Test scope guards (exists = owner/planet/event_target:...) - several CP26 fixes documented above exist purely to avoid scope-context errors caught in error.log. This pattern is common in the mod and should be reused for new content.
  • Watch for performance regressions: some events have been hard-disabled mid-development (hornblower_country_events.txt, §2) after causing game freezes. Test new pulses/periodic events on long-running games before shipping them.
