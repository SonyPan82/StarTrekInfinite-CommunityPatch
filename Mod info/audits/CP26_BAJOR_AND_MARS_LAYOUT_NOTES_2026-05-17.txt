CP26 - BAJOR / MARS LAYOUT NOTES
Date: 2026-05-17

1) Bajor repositioning

Problem observed:
- Bajor was visually extremely close to Cardassia on the fixed Alpha/Beta map.
- This gave the impression that Bajor was almost embedded in Cardassian space.

Audit:
- Bajor is heavily referenced by flags / event targets / quest nodes / wormhole
  logic, but those references rely on the Bajoran initializer and event targets,
  not on the previous raw map coordinates.
- Draygo is a custom static system initializer.
- Klaestron is only an uncontrolled generic system.

Decision retained:
- swap Bajor with Klaestron
- do not swap Bajor with Draygo

Reason:
- Klaestron is the lowest-risk candidate
- Draygo has a custom initializer and is a worse target for a simple position
  swap
- Bajor keeps the same system ID / initializer / event flags, only its position
  changes on the fixed map

Files updated:
- map/setup_scenarios/Alpha-Beta_medium.txt
- map/setup_scenarios/tutorial.txt


2) Mars visual pattern

Problem observed:
- Mars looked too close to Luna in the outliner / planet visuals
- both were using subclass `psc_class_h`

Audit:
- Mars already uses picture `pc_mars`
- Vulcan uses `psc_class_m`, which gives a more convincing dry rocky pattern
  than Luna's subclass

Decision retained:
- keep Mars as `pc_barren`
- keep picture `pc_mars`
- change subclass from `psc_class_h` to `psc_class_m`

Reason:
- this changes the visual pattern without changing the lore identity of Mars
- it is a small and low-risk visual improvement

File updated:
- common/solar_system_initializers/ufop/ufop_sol_initializer.txt
