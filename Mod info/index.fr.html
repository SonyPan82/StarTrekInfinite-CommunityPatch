CP26 - Documentation technique

Documentation de reference pour Community Patch 2026 (CP26), un overhaul communautaire pour Star Trek: Infinite. Redigee pour les contributeurs : que modifie CP26, comment, et ou.

1. Vue d'ensemble

CP26 est un overhaul communautaire pour Star Trek: Infinite (1.0.7). Il agit selon deux mecanismes Paradox distincts :

Remplacement complet (replace_path)

43 fichiers vanilla sont entierement remplaces par une copie modifiee de CP26 (declares dans descriptor.mod). Le fichier vanilla original est totalement ignore ; CP26 doit repliquer tout son contenu utile en plus de ses propres modifications.

Addition pure

Tout le reste (des centaines de fichiers) s'ajoute simplement au chargement normal du jeu : nouveaux evenements, especes, quetes, megastructures, etc. Paradox charge automatiquement tout fichier .txt/.gfx/.asset present dans les dossiers reconnus - pas besoin de les declarer dans descriptor.mod.

Conventions de nommage

Comprendre les prefixes de fichiers est la cle pour naviguer dans le mod :

PrefixeSignification
hornblower_*Fichiers du mod de base "Hornblower" (la fondation sur laquelle CP26 est construit) - presents dans replace_path quand modifies
aa_*"Ambient/AI" - factions IA non jouables au demarrage (Ferengi, Gorn, Orion, Tholian) et leurs sous-systemes (gouvernement, civics, personnalites, init de systeme)
cp26_*Contenu narratif/systemique original de CP26 (arcs de quete, megastructures, projets speciaux)
zz_cp26_*Correctifs, reglages fins ou ajouts tardifs de CP26 - souvent des fixes de bugs vanilla/Hornblower ou des reglages d'equilibrage
zz_mm_*Megastructures portees depuis un mod tiers "Mid-game Megastructures" (Dyson Swarm, Fusion Hub, Lifter)
00_*, 01_*, 02_*...Prefixe numerique = ordre de chargement Paradox (les fichiers se chargent par ordre alphabetique dans un dossier)

Le motif "stub + split"

Plusieurs fichiers vanilla volumineux declares en replace_path ont ete reduits a un simple commentaire d'une ligne (ex. common/quest_tree_nodes/00_ufop_nodes.txt, common/solar_system_initializers/hornblower_initializers.txt, events/hornblower_game_start.txt). Leur contenu reel a ete eclate en dizaines de fichiers individuels dans le meme dossier (ex. qt_ufop_a1.txt, game_start_101.txt). Paradox charge automatiquement tous les .txt d'un dossier, donc ce decoupage fonctionne sans declaration supplementaire - et permet d'ajouter de nouveaux noeuds/evenements sans jamais toucher au fichier remplace.

Pour un futur modder : si vous cherchez le contenu d'un noeud de quete UFOP ou d'un evenement game_start, ne cherchez pas dans 00_ufop_nodes.txt ou hornblower_game_start.txt - ils sont vides. Cherchez le fichier qt_ufop_<nom>.txt ou game_start_<id>.txt correspondant.

Systeme technologique & deverrouillage

Chaque technologie a un area (physique/societe/ingenierie), un tier (0-5) et une category. Les couts et poids de base reutilisent les variables scriptees vanilla par palier (@tier1cost1...@tier5cost3), sauf les technologies de deverrouillage de coque, qui utilisent toutes une seule variable partagee, @specialhullweight, au lieu du poids generique de palier.

Le verrouillage par faction passe par potential (retire completement la technologie de l'arbre si faux, pas seulement grisee), verifie contre des triggers scriptes definis dans common/scripted_triggers/z_aa_scripted_triggers.txt :

is_ferengi_empire = { OR = { is_country_type = ferengi_alliance  has_country_flag = ferengi  has_country_id = "ferengi" } }
is_gorn_hegemony  = { OR = { is_country_type = gorn_hegemony  has_country_flag = gorn_hegemony  has_country_flag = gorn  has_country_id = "gorn" } }
is_orion_syndicate= { OR = { is_country_type = orion_syndicate  has_country_flag = orion_syndicate  has_country_flag = orion  has_country_id = "orion" } }

is_ufop/is_klingon/is_romulan/is_cardassian sont les triggers equivalents fournis par Hornblower. Aucun trigger is_tholian n'existe - les Tholiens sont verrouilles uniquement au niveau des ship_sizes (potential_country = { has_country_id = tholian }), pas cote technologie, ce qui explique l'absence de technologies de coque dediees pour eux (voir le tableau par faction plus bas).

Le timing IA : les technologies de coque utilisent un weight_modifier indexe sur years_passed (facteur 0 avant une annee seuil, en hausse ensuite) plus un multiplicateur ai_weight separe reserve aux empires IA. C'est le mecanisme derriere l'acceleration de deverrouillage IA deja notee en §2 (les fenetres de la chaine generique ont ete compressees a environ un quart de la duree vanilla).

Une technologie, plusieurs habillages par faction (triggered_config) : la chaine de coques generique a 5 paliers - tech_corvette_unlock, tech_destroyer_unlock, tech_cruiser_unlock, tech_battleship_unlock, tech_titan_unlock - est un seul identifiant de technologie par palier, sans restriction potential, portant un bloc triggered_config par faction qui ne change que le title/desc/icon affiche. Rechercher "Developpement de Croiseur" montre l'Excelsior a un joueur UFOP et le K'tinga a un joueur Klingon - meme technologie, memes prerequis, meme cout de recherche, vaisseau different a l'arrivee.

Sur mesure contre partage : les factions avec leur propre chaine de coques en plusieurs etapes (UFOP, Klingon, Gorn, Orion, Romulien) obtiennent un rythme weight_modifier propre, des prerequis coque-a-coque (la coque tardive d'une faction necessite sa propre coque precedente, pas seulement le palier generique), et des verrous par flag de quete - rien de tout cela n'est possible sur une technologie unique partagee avec seulement des icones cosmetiques differentes. Les Cardassiens et les Ferengi n'ont aucun fichier de coque dedie et s'appuient entierement sur l'habillage de la chaine partagee.

Technologies cachees/octroyees par quete : tech_lamarr_unlock, tech_odyssey_unlock et tech_defiant sont a weight_modifier = { factor = 0 } (jamais tirees naturellement) et sont octroyees directement via give_technology depuis des noeuds d'arbre de quete (qt_ufop_upgrade_voyager_lamarr.txt, qt_ufop_upgrade_enterprise_odyssey.txt, qt_ufop_b7.txt) - hidden = yes posait probleme, donc weight = 0 est utilise comme contournement.

Evitement des technologies dupliquees : tech_warp_speed_increase_1 et _2 ont ete retirees de leurs fichiers vanilla/Hornblower d'origine avec un commentaire expliquant qu'elles sont redefinies dans zz_cp26_warp_techs.txt pour eviter une erreur moteur "Duplicate technology" (une nouvelle tech_warp_speed_increase_3 a ete ajoutee au passage). C'est le seul endroit de common/technology/ ou une technologie est deliberement deplacee pour contourner cette erreur.

9. Decisions d'equilibrage

  • Plafond de flotte militaire (~36 vaisseaux de ligne) : cp26_under_reduced_fleet_military_cap plafonne les coques de ligne a 36 par empire (common/scripted_triggers/aa_scripted_triggers.txt) pour garder des combats lisibles, environ "3 flottes de 12", au lieu des amas de fin de partie vanilla. Le reglage complementaire par flotte (COMMAND_LIMIT base 24 / max 96) est ecrit mais actuellement desactive dans common/defines/zz_cp26_reduced_fleet_scale_defines.txt en attente d'une verification de performance - seul le plafond global de 36 est actif.
  • Palier technologique de commandement raccourci (4 → 2 paliers) : avec le plafond de flotte en place, l'ancienne echelle +15/+25/+35/+45 permettait de depasser largement la capacite reelle. Reduite a +10/+15 via la technologie, la difference etant deplacee vers des batiments militaires par planete (Base Militaire +4, QG Militaire +8) pour que le commandement suive le territoire plutot que la seule recherche.
  • Palier des torpilles et cout en tetryons : les torpilles a photons passent d'un cout en alliages de tier 3 a tier 5, plus un nouveau cout en tetryons, pour que les ameliorations d'armes de fin de partie entrent en concurrence avec boucliers/reacteurs pour les memes ressources strategiques au lieu d'etre un puits d'alliages gratuit.
  • Buffs de ressources de depart IA (Klingon/Cardassien/Ferengi uniquement) : le code de budget IA vanilla ne construit pas d'avant-poste sous 75 influence ni de vaisseau colonisateur sous 2000 nourriture stockee, des seuils que ces trois departs n'atteignaient pas avant de nombreuses annees de jeu. Corrige par des injections de depart reservees a l'IA (events/zz_cp26_major_start_balance.txt, cp26_start_balance.1) : Klingon +150 alliages/+50 influence, Cardassien +200 alliages/+75 influence, Ferengi +200 alliages. Les departs UFOP, Romulien, Tholien, Gorn et Orion n'ont pas ete touches - leurs budgets franchissent deja ces seuils naturellement.
  • Courbe de vitesse warp : la vitesse de deplacement interstellaire de base est reduite d'environ 35% (WARP_INTERSTELLAR_TRAVEL_SPEED 0.1 → 0.065) pour que la galaxie paraisse plus grande en debut de partie, recuperee progressivement via 3 technologies jusqu'a 120% de la valeur vanilla a "Warp 7" - une courbe deliberement lente au depart et rapide en fin de partie, pas un simple nerf plat.
  • Points de vie des vaisseaux heros divises par deux : le Voyager (7000 → 2500 PV) et le vaisseau heros D'deridex (10000 → 4500 PV) etaient quasiment increvables combines a leur chance de degagement vanilla deja elevee (1.50 / 1.20) - les deux valeurs de PV ont ete revues a la baisse, la chance de degagement laissee telle quelle.
  • Taille de slot de flotte des cuirasses corrigee : les cuirasses Tholiennes, Orion et Gorn avaient size_multiplier = 8 mais seulement fleet_slot_size = 3 contre 4 pour ce niveau de puissance selon le standard vanilla - un avantage cache d'environ 33% sur le plafond de flotte. Corrige a 4 pour les trois.
  • Civics des factions mineures reduits, pas redessines : les civics d'Infinite n'ont que des bonus, jamais de malus integre, donc les civics de factions mineures surdimensionnes (ex. bonus de stabilite de l'isolationnisme Tholien 10 → 5, reduction de l'usure de guerre du predatisme Gorn -30% → -25%) ont ete reduits numeriquement plutot que dotes de nouveaux malus, en restant plus forts que les civics des grandes puissances sans etre excessifs.

Ajouter un nouvel empire majeur/regional (archetype "contender")

Recette complete : classe d'espece, culture graphique, autorite, civics (avec potential = { always = no } pour qu'ils ne soient pas selectionnables par le joueur), 3 tailles de vaisseau, templates de section/composant, designs de vaisseau globaux, fichiers .asset, un initialiseur de systeme stellaire, un evenement on_game_start, un hook on_actions, 2 entrees de fichier de scenario, des ajustements de fraction de vaisseaux dans le type de pays contender, et la localisation EN/FR.

Deux pieges a connaitre avant de commencer :

  • late_init_effect dans un initialiseur de systeme n'est pas appele de maniere fiable pour les empires de type contender generes via setup_scenarios - la mise en place de la capitale doit passer par un evenement on_game_start, sinon l'empire se retrouve avec un pays et une espece mais aucune capitale possedee.
  • Ne jamais appeler create_ship_design/add_ship_design dans un initialiseur de systeme - cela peut interrompre silencieusement late_init_effect en cours d'execution (c'est ainsi que le deuxieme vaisseau de depart des Ferengi avait disparu pendant le developpement).

Utilisez type = contender pour un empire IA rival a visibilite normale, ou un type de pays dedie (comme ferengi_alliance pour les Ferengi) quand observable = no / show_in_contacts_list = no sont necessaires pour un empire cache jusqu'au premier contact.

11. Corrections de bugs a impact durable

  • Chantier naval de capitale IA : les empires IA pouvaient demarrer sans chantier naval de capitale fonctionnel, une asymetrie face au joueur. Corrige par cp26_ai_shipyard.1 (common/on_actions/zz_cp26_on_game_start.txt), qui force la construction d'un starport de capitale et d'un module chantier naval pour les pays majeurs/mineurs/contender controles par l'IA.
  • Crash de file de construction : create_colony immediatement suivi du retrait de l'abri de colonie et de l'ajout du batiment de capitale dans le meme tick corrompait la file de construction du moteur au moment de la sauvegarde. Corrige en supprimant totalement le retrait d'abri au meme tick dans tous les scripts de colonie concernes (Luna, Mars, Tholia, Orion, Gorn, Denobula, Glintara).
  • Chaine "The Freed" de la crise Borg : le jeu de base livre la chaine finale de la crise Borg et les 3 evenements du projet special Voyager (PROBE_DEFENSES, COUNTERACT_MEASURES, DELIVERANCE) avec leur reference event_chain commentee, empechant le journal de situation de se resoudre. Decommente et cable a borg_crisis_end / borg_crisis_end_the_freed.
  • Evenement de bonus de premier contact UFOP (country.27500) : utilisait le scope invalide root.from, echouant silencieusement ou appliquant le bonus d'opinion au mauvais pays. Corrige en who = from avec des gardes anti-double-traitement.
  • Impasses de mission pour empires mineurs : plusieurs evenements mission.* reservaient toutes les options a is_ufop/klingon/romulan/cardassian, laissant les mineures IA (Bajoran, Farian, etc.) sans aucun choix valide et l'evenement bloque. 13. Tester avec la console de debug

Un guide pas a pas pour tester les arcs narratifs de CP26 sans devoir les declencher naturellement en jouant - ecrit pour quelqu'un qui n'a jamais ouvert la console de Stellaris/Infinite.

Ouvrir la console

  1. Lancez une partie normale (pas en Ironman - Ironman desactive completement la console).
  2. Appuyez sur la touche juste en dessous de Echap, a cote du 1 (generalement `/~ sur un clavier US, § ou ² sur certains claviers europeens/AZERTY) pour ouvrir la barre de console en bas de l'ecran.
  3. Tapez une commande puis Entree. La console reste ouverte - vous pouvez enchainer d'autres commandes.
  4. Sauvegardez votre partie avant de tester quoi que ce soit de destructif ; les commandes console peuvent desynchroniser une partie multijoueur et parfois corrompre une sauvegarde si elles sont mal utilisees (testez toujours sur une copie de sauvegarde, jamais sur votre campagne principale).

Commandes generales (vanilla, pas specifiques a CP26)

CommandeCe qu'elle fait
event <id_evenement>Declenche immediatement un country_event sur le pays actuellement joue. C'est l'outil principal pour tester les evenements narratifs de CP26 - voir les tableaux d'arcs ci-dessous pour de vrais identifiants.
effect <effet>Execute un effet script brut, ex. effect add_country_flag = mon_flag ou effect remove_global_flag = mon_flag. Sert a poser/retirer les flags qui verrouillent les arcs de CP26.
play <id_pays>Change l'empire que vous jouez/controlez - permet de tester la reaction d'un meme arc pour chaque grande puissance sans relancer de partie.
debugtooltipActive un affichage montrant les identifiants internes (ID pays, ID planete, ID flotte...) au survol de la carte - utile pour trouver le <id_pays> de la commande play ci-dessus.
research_technology <id_tech>Termine et accorde instantanement une technologie donnee.
add_research_option <id_tech>Ajoute une technologie au pool de recherche sans l'accorder (il faut ensuite la rechercher normalement).
research_all_technologiesAccorde toutes les technologies recherchables - utile pour sauter directement aux coques de fin de partie.
instant_buildActive/desactive la construction instantanee - batiments, vaisseaux et megastructures se terminent immediatement.

event ne fonctionne que pour un country_event. Un planet_event ne peut pas etre appele directement avec event - il faut l'envelopper dans un effect qui trouve d'abord la planete, ex. effect = { random_galaxy_planet = { limit = { has_planet_flag = planet_mars } planet_event = { id = cp26_a500.1 } } } (voir le tableau de l'arc Mars ci-dessous pour un exemple fonctionnel).

14. Pour les futurs contributeurs

  • Ne modifiez jamais un fichier vanilla directement dans le dossier de jeu - toute modification doit passer par un fichier CP26, soit via replace_path (fichier entier remplace, declare dans descriptor.mod), soit via un fichier additionnel autonome.
  • Avant de chercher un contenu dans un fichier "racine" (00_ufop_nodes.txt, hornblower_initializers.txt, hornblower_game_start.txt), verifiez s'il n'est pas reduit a un stub - voir le motif stub+split en §1.
  • Respectez les prefixes de nommage existants (§1) pour rester coherent : cp26_* pour du contenu narratif neuf, zz_cp26_* pour des correctifs/reglages tardifs.
  • Le CHANGELOG.md est en retard - si vous le mettez a jour, verifiez d'abord l'etat reel du code (comme cette page l'a fait) plutot que de vous fier aux dernieres entrees.
  • Testez les gardes de scope (exists = owner/planet/event_target:...) - plusieurs correctifs CP26 documentes ci-dessus existent uniquement pour eviter des erreurs de contexte de scope detectees dans error.log. Ce motif est courant dans le mod et doit etre reproduit pour tout nouveau contenu.
  • Attention aux regressions de performance : certains evenements ont ete desactives en urgence en cours de developpement (hornblower_country_events.txt, §2) suite a des gels de partie. Testez les nouveaux pulses/evenements periodiques sur de longues parties avant de les livrer.
