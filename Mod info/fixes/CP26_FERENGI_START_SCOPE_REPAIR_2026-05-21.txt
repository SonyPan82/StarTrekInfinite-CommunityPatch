CP26 FERENGI START SCOPE REPAIR - 2026-05-21

Issue
- Starting a new game as the Ferengi could still end in immediate defeat.

Cause
- ferengi_player_initializer was still running direct owner/colony creation logic on the start world.
- That logic was using Ferengi-specific scope assumptions instead of the normal prescripted-player pattern.
- cp26_setlik.4 could also pick any planet with the ferengi_capital flag, which was risky if more than one such planet existed during startup.

Fix
- Replaced the player initializer late_init_effect with a safe capital bootstrap that only:
  - creates the colony if needed
  - adds the capital building
  - adds the intended starting districts
  - creates 16 pops from owner_main_species
- No direct event-target owner assignment is done in the playable Ferengi initializer anymore.
- cp26_setlik.4 now targets only a ferengi_capital planet already owned by ROOT.
- cp26_spawn_repair.1 now does the same for the Ferengi repair pass.

Files
- common/solar_system_initializers/aa_ferengi_initializer.txt
- events/zz_cp26_setlik_fix.txt
- events/zz_cp26_spawn_repair_events.txt

Expected result
- A new Ferengi game should no longer fail instantly at start.
- The Ferengi capital event should no longer latch onto a wrong ghost capital candidate.
