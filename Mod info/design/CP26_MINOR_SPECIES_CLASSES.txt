1. PROBLÈME D'ORIGINE (vanilla)
--------------------------------------------------------------------------------
Star Trek Infinite regroupe TOUS les peuples mineurs (Acamarian, Bajoran,
Betazoid, Bolian, Boslic, Cairn, Farian, Hupyrian, Idanian, Iyaaran, Kaelon,
Kesprytt, Ktarian, Lissepian, Malcorian, Pelian, Talarian, Tanugan, Trill...)
sous une SEULE et même classe : "HRB" (Humanoid Race - Beta).

14 des 21 fichiers prescripted minors portent même un commentaire explicite :

    class = "HRB" # TODO: Create custom class

Conséquences :
  - Tous les minors partagent le MÊME pool de portraits (vulcan, klingon,
    cardassian, fedhuman, etc. mélangés).
  - Tous utilisent la MÊME graphical_culture (ufop_01).
  - Aucune distinction visuelle ou lore entre un Bajoran spirituel et un
    Talarian belliqueux - mécaniquement identiques au moteur.

3. CHOIX TECHNIQUES
--------------------------------------------------------------------------------
- archetype = BIOLOGICAL : identique à HRB → zero impact mécanique.
- resources = {} : aucune modification d'upkeep ni de production de pop.
- portraits restreints au thème : c'est le SEUL effet observable en jeu
  (visuel uniquement).
- HRB_HARDY utilise graphical_culture = minor_01 pour différencier l'aspect
  cités/vaisseaux des minors "rudes" des UFOP.
- La classe générique "HRB" originale est conservée intacte dans
  02_hornblower_species_classes.txt (utilisée par randoms et autres).

4. RISQUES & RÉVERSIBILITÉ
--------------------------------------------------------------------------------
- Risque équilibrage : NUL. Les classes sont identiques mécaniquement.
- Risque visuel : si un portrait n'existe pas dans le .gfx, le moteur tombe
  sur un placeholder. Tous les portraits utilisés (bajoran, betazoid, trill,
  etc.) sont déjà déclarés dans la liste HRB vanilla → garantis présents.
- Reversibilité : 1 commit de revert (supprimer les patches `class = HRB_*`
  vers `class = HRB`, supprimer le fichier zz_cp26_minor_species_classes.txt).
