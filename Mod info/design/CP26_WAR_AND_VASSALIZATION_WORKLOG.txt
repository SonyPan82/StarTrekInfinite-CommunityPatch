1) Vassalization restoration
- Restored and expanded a direct diplomatic vassalization flow outside vanilla-only restrictions.
- Added / worked on a proposal flow where one empire can propose vassalization to another.
- Intended result:
  - target receives a proposal
  - target can accept or refuse
  - refusal grants a temporary subjugation casus belli
- Related local work:
  - common/diplomatic_actions/00_hornblower_actions.txt

2) War-goal peace / "Demand Surrender" proposal
- Added a separate diplomatic action intended for wartime use:
  - action_cp26_offer_war_goal_peace
- Intended result:
  - actor sends a war-goal acceptance proposal during war
  - recipient gets a pop-up after a short delay
  - recipient accepts or refuses
  - accept should end the war with demand_surrender
  - refuse should keep the war going
- Related event chain:
  - cp26_vassalization.6
  - cp26_vassalization.7
  - cp26_vassalization.8
- Important finding:
  - this is not a Workshop feature that was lost
  - this is custom CP26 work added locally

3) War screen / "Impose War Goal" attempts
- Multiple attempts were made to expose a visible "impose war goal" style button in the war overview.
- We tested:
  - injecting force_demands into the visible offer_peace bar
  - replacing / renaming the neutral_zone slot
  - trying to reuse vanilla peace bar widget names
- Result:
  - visible button could appear
  - but the behavior was not reliable
  - replacing neutral_zone caused GUI errors because the engine expects that slot to exist
- Conclusion:
  - the waroverview GUI is not a safe place to force this mechanic
  - the cleaner path is a separate wartime diplomatic action + event flow
- File involved:
  - interface/waroverview.gui

4) Wartime border opening / war access
- Added support work intended to open movement access during wars.
- Goal:
  - if empires are at war, fleets should not get blocked by closed borders
  - neutral zones should not trap movement during active wars
- Related file:
  - events/zz_cp26_war_access_events.txt
  - common/on_actions/zz_cp26_war_access_on_actions.txt
- Effect used:
  - set_closed_borders = { status = no forced = 5 }
- Purpose:
  - reduce cases where war participants cannot enter enemy-adjacent systems

5) Puppet state / subject-path experiments
- Several tests were made around using the game's puppet-state style diplomatic hooks.
- Purpose:
  - see whether an already-wired vanilla diplomatic action could be reused
  - see whether puppet-state logic could stand in for missing vassalization support
- Result:
  - useful for testing visibility / availability
  - but not a clean substitute for a true accept/refuse war-goal proposal flow
- Important gameplay concern raised:
  - puppet-state behavior can distort normal federation / integration logic
  - puppet-state behavior can auto-resolve in ways that are not appropriate for the intended CP26 war flow

6) Occupation / occupied-state war-goal work

- Related local file:

17) Warp travel study and CP26 options
- Confirmed that Infinite exposes separate script hooks for:
  - ship_speed_mult: local / physical ship movement
  - ship_warp_speed_mult: interstellar warp travel speed
  - ship_warp_cooldown_mult: delay between warp moves
  - warp_range_add: country-level warp reach
- Decision taken:
  - keep early and mid game unchanged
  - add only a small late-game traversal bonus through a final warp-speed tech layer
  - avoid the fake "huge warp_range_add" approach for military ships
- Implemented:
  - restored / added tech_warp_speed_increase_2 as a light late-game warp-speed bonus
  - changed military ships to use science-ship style warp behavior instead (`ignores_warp_range = yes` + `ship_hyperlane_range_add = 1`)
  - removed the earlier unlimited-warp popup experiment because it could create incorrect warp-bubble behavior
