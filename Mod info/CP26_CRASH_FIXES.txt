FIX 10 - Crash SIGFPE à la génération de la galaxie
=============================================================================

SYMPTOME :
  Crash SIGFPE (division par zéro flottante) au lancement d'une nouvelle
  partie, pendant la phase de génération de la galaxie.
  Message dans les logs : "invalid initializer 'bajoran_bajor_initializer'"

CAUSE :
  Les fichiers de scénario de carte Alpha-Beta_medium.txt et tutorial.txt
  référencent bajoran_bajor_initializer par nom littéral. Le fichier CP26
  qui définissait cet initialiseur a été supprimé lors du retrait de l'arc
  Bajoran (wormhole). Le moteur ne trouve plus l'initialiseur → SIGFPE.

CORRECTION :
  Restauration de bajoran_bajor_initializer.txt dans
  common/solar_system_initializers/other_owned/ sans le contenu spécifique
  à l'arc wormhole (pas de create_ambient_object cp26_bajoran_wormhole,
  pas de set_planet_flag = denorios_belt_target).
  Le système Bajor est conservé avec sa structure complète (étoile G,
  10 planètes, Bajor XI comme planète habitable avec pops et flags mapo_colony
  + mipo_colony, event targets bajoran_planet/country/system).

FIX 11 - Gel infini pendant les combats (freeze / boucle infinie)
=============================================================================

SYMPTOME :
  La partie se bloque indéfiniment pendant les combats impliquant des
  vaisseaux avec 0 officiers (pirates, vaisseaux de crise).
  Aucun crash, le jeu gèle sans consommer de CPU excessif.

CAUSE :
  OFFICERS_MAX_FIRE_RATE_PENALTY = 1.25 dans
  common/defines/zz_cp26_reduced_fleet_scale_defines.txt.
  Formule du moteur : fire_rate = base × (1 − penalty × deficit_ratio)
  Avec 0 officiers sur un vaisseau (pirates : Dreadnought + Redoubt),
  deficit_ratio = 1.0 → fire_rate = base × (1 − 1.25) = valeur négative.
  Le simulateur de combat boucle indéfiniment sur un taux de tir négatif.

  La valeur vanilla est 1.0, ce qui donne fire_rate = 0 au minimum.
  CP26 avait augmenté la pénalité à 1.25 pour amplifier l'effet des officiers,
  sans réaliser que cela cassait les vaisseaux sans officiers.

CORRECTION :
  OFFICERS_MAX_FIRE_RATE_PENALTY ramené de 1.25 à 1.0 (valeur vanilla).
  Fichier : common/defines/zz_cp26_reduced_fleet_scale_defines.txt.
  Les autres paramètres officers (SHIP_OFFICERS_ADD_PERCENTAGE = 0.12,
  OFFICERS_MAX_FIRE_RATE_BONUS = 0.1, etc.) restent inchangés.

VALIDATION :
  Confirmé par le joueur après test en partie : "oui c'est bon je crois
  que c'était ça ouf".

FIX 1 - CConstructionQueueManager::DailyUpdate (SIGSEGV)
=============================================================================

FICHIER MODIFIE :
  common/special_projects/00_projects_hornblower.txt
  Projet : CARDASSIAN_OCCUPATION_TIER_1

SYMPTOME :
  Crash SIGSEGV dans CConstructionQueueManager::DailyUpdate.
  Se produit en cours de partie, typiquement quand une guerre impliquant
  les Cardassiens se termine ou qu'une planète occupée change de statut.

CAUSE :
  Le abort_trigger du projet utilisait un bloc NAND qui accédait directement
  aux event_targets conquered_planet_scope et new_owner_scope sans verifier
  leur existence au prealable. Le moteur Paradox evalue TOUTES les conditions
  d'un NAND simultanement (pas de court-circuit), donc meme si un scope est
  null, le code tente quand meme d'y acceder - null pointer dereference.

  Les guards exists avaient ete places en commentaire dans le code original :
    # exists = event_target:conquered_planet_scope
    # exists = event_target:former_owner_scope
    # exists = event_target:new_owner_scope
  Les reintegrer dans le NAND n'aurait pas suffi (meme probleme de
  evaluation simultanee).

  De plus, current_war_scope ne se sauvegarde que si la guerre utilise
  wg_occupation (vanilla). Les nouvelles guerres CP26 (wg_cp26_forced_occupation)
  laissent ce scope null des le debut, ce qui aurait rendu le projet inutilisable
  si on avait conserve cette condition dans le trigger.

CORRECTION :
  Remplacement du NAND par un OR avec exists guards en premiere position.
  L'OR court-circuite des qu'une branche est vraie, ce qui empeche
  l'acces aux scopes nuls. current_war_scope retire du abort_trigger -
  l'occupation est definie par l'etat de la planete, pas par la guerre active
  (comportement plus fidele : la planete peut rester sous controle cardassien
  apres un status quo). Les blocs on_success et on_fail gerent deja
  current_war_scope independamment avec leurs propres guards exists.

FIX 2 - CPlanetManager::DailyUpdate / DailyUpdateAllUnhabitableSelfDontReadOthers (SIGSEGV)
=============================================================================

FICHIERS MODIFIES :
  common/districts/z_hornblower_romulan_districts     (district_civil_forum)
  common/districts/10_xl_map_remus_districts.txt      (2 districts Remus)
  common/districts/aa_breen_districts.txt             (2 districts Breen)
  common/districts/aa_gorn_districts.txt              (district_gorn_hunting)
  common/districts/aa_orion_districts.txt             (district_orion_market)

SYMPTOME :
  Crash SIGSEGV dans CPlanet::DailyUpdateAllUnhabitableSelfDontReadOthers,
  appele depuis CPlanetManager::DailyUpdate. Se produit en cours de partie,
  de facon aleatoire. Le crash peut toucher plusieurs threads simultanement
  (traitement parallele des planetes).

CAUSE :
  Le bloc show_on_uncolonized de ces districts accede au scope from
  (l'empire qui considere la colonisation) sans verifier son existence.
  Ce bloc est evalue sur TOUTES les planetes inhabitables a chaque jour
  de jeu. Dans certains contextes (evaluation en thread parallele, planetes
  sans colonisateur potentiel), from est null - null pointer dereference.

  Exemple du probleme :
    show_on_uncolonized = {
        is_colonizable = yes
        from = { is_romulan = yes }   <-- crash si from est null
    }

  Le pattern correct existait deja dans aa_tholian_districts.txt mais
  n'avait pas ete applique de facon consistante aux autres fichiers.

CORRECTION :
  Ajout de exists = from comme premiere condition dans chaque bloc
  show_on_uncolonized concerne. L'OR court-circuite immediatement si from
  est null, sans jamais tenter d'acceder au scope.

  Exemple apres correction :
    show_on_uncolonized = {
        exists = from                 <-- guard en premiere position
        is_colonizable = yes
        from = { is_romulan = yes }
    }

  Aucun impact sur le gameplay : ces districts restent visibles exactement
  pour les memes empires qu'avant, simplement sans crasher quand from
  n'est pas disponible.

FIX 3 - CConstructionQueueManager::DailyUpdate (SIGSEGV) - meme crash, autre projet
=============================================================================

FICHIER MODIFIE :
  common/special_projects/00_projects_hornblower.txt
  Projet : MIPO_ASSIMILATION_PROJECT

SYMPTOME :
  Identique au Fix 1 - meme fonction, meme offset (+816).
  Se produit quand le minor power cible est detruit ou libere de sa
  vassalisation pendant que le projet d'assimilation est actif.

CAUSE :
  Le abort_trigger accedait directement a event_target:mipo_to_be_assimilated
  sans verifier son existence :
    abort_trigger = {
        event_target:mipo_to_be_assimilated = {
            is_subject = no
        }
    }
  Si le minor power est detruit (event_target null), crash SIGSEGV.

CORRECTION :
  Enveloppe dans un OR avec exists guard en premiere position :
    abort_trigger = {
        OR = {
            NOT = { exists = event_target:mipo_to_be_assimilated }
            event_target:mipo_to_be_assimilated = { is_subject = no }
        }
    }
  Le projet avorte aussi si la cible n'existe plus, ce qui est le
  comportement logique attendu.

FIX 4 - EXCEPTION_ACCESS_VIOLATION - Action diplomatique mal typée (2026-05-08)
=============================================================================

FICHIER MODIFIE :
  common/diplomatic_actions/00_hornblower_actions.txt
  Action : action_cp26_offer_war_goal_peace

CAUSE :
  La combinaison is_listed = yes + auto_accepted = yes + action_type = aggressive
  n'est supportee par aucune autre action dans le jeu de base. Le moteur
  echoue a enregistrer correctement l'action, laissant un pointeur null dans
  la table interne des actions diplomatiques. Quand l'AI itere cette table,
  elle dereference ce pointeur - crash.

CORRECTION :
  action_type = aggressive remplace par action_type = negative.
  Aucun impact gameplay : le changement ne modifie que la couleur de
  l'icone dans l'interface diplomatique.

FIX 5 - Iterator invalidation - cp26_war_access.2 sur on_daily_pulse (2026-05-08)
=============================================================================

FICHIERS MODIFIES :
  common/on_actions/zz_cp26_war_access_on_actions.txt
  events/zz_cp26_war_access_events.txt

SYMPTOME :
  Surcharge CPU et crash potentiel pendant les guerres actives, notamment
  en milieu de partie avec plusieurs conflits simultanes.

CAUSE :
  cp26_war_access.2 etait declare sur on_daily_pulse_country : il s'executait
  chaque jour pour chaque empire. En guerre, la boucle every_war { every_war_participant
  { set_closed_borders } } generait des centaines d'appels par jour, risquant
  une invalidation d'iterateur sur les objets war en modification concurrente.
  Le forced = 5 expirait avant le prochain refresh, creant des fenetres de
  bordures fermees.

CORRECTION :
  Deplacement sur on_monthly_pulse_country. forced = 5 -> forced = 40 pour
  garantir que les bordures restent ouvertes entre deux refreshs mensuels.

FIX 7 - kill_pop sans filtre dans l'evenement Romulien country.9016 (2026-05-08)
=============================================================================

FICHIER MODIFIE :
  events/hornblower_country_events.txt
  Evenement : country.9016 (Tan Zhekran Poison - Fail)

SYMPTOME :
  Warning "Broken Save: Army X parent Pop Y doesn't remember them" dans
  les saves Romuliens en milieu/fin de partie.

CAUSE :
  La branche else de l'evenement tuait une pop aleatoire sans filtre sur
  Romulus quand aucune pop avec le job centurion_romulan n'etait presente.
  Le moteur 1.0.7 ne nettoie pas toujours le lien armee-pop lors d'un
  kill_pop scripte - la pop disparait mais l'armee reste orpheline.

CORRECTION :
  Suppression du bloc else. Si Romulus n'a plus de centurions, l'evenement
  ne produit pas d'effet secondaire (comportement neutre preferable a un
  kill_pop aveugle).

FIX 8 - kill_pop pouvant vider une colonie (unique_mechanic.1 Cardassien) (2026-05-08)
=============================================================================

FICHIER MODIFIE :
  events/hornblower_country_events.txt
  Evenement : unique_mechanic.1

SYMPTOME :
  Warning "Broken Save: Army X parent Pop Y doesn't remember them" sur
  les empires Cardassiens possedant des populations esclaves. Possible
  colonie "possedee mais vide" si toutes les pops non-cardassienne sont
  eliminee sur une planete.

CAUSE :
  Le mecanisme unique Cardassien (25% de chance par planete de tuer une
  pop non-cardassienne) pouvait tuer la DERNIERE pop non-cardassienne sur
  une planete ne contenant que des esclaves non-cardassiens. La planete
  se retrouvait avec un proprietaire mais zero pop - etat instable generant
  des armies orphelines et potentiellement un crash.

CORRECTION :
  Ajout d'un guard dans la limite du random_owned_pop : la pop cible doit
  se trouver sur une planete qui possede AU MOINS une pop cardassienne.
  Garantit qu'une colonie ne peut jamais se retrouver entierement vide
  par ce mecanisme.

FIX 9 - CPlanetManager::DailyUpdate - 3 districts jeu de base non couverts (2026-05-08)
=============================================================================

FICHIER CREE :
  common/districts/zz_cp26_district_fixes.txt

SYMPTOME :
  Crash SIGSEGV identique au Fix 2, persistant malgre ce dernier.
  Les 5 fichiers couverts par Fix 2 ne suffisaient pas : 3 districts
  du jeu de base n'etaient pas overrides par CP26 et portaient le meme bug.

CAUSE :
  Le jeu de base (Infinite) contient 4 fichiers de districts Hornblower avec
  le meme pattern defaillant :
    06_hornblower_ufop_districts.txt      → district_culture
    07_hornblower_klingon_districts.txt   → district_hunting_grounds
    08_hornblower_romulan_districts.txt   → district_civil_forum  (deja fixe)
    09_hornblower_cardassian_districts.txt → district_labor_camp

  district_civil_forum etait deja override par CP26 (z_hornblower_romulan_districts).
  Les trois autres (culture, hunting_grounds, labor_camp) ne l'etaient pas -
  le jeu de base les chargeait avec le bug intact.

CORRECTION :
  Creation de zz_cp26_district_fixes.txt qui override les 3 districts manquants
  avec exists = from en premiere condition de chaque show_on_uncolonized.
  Contenu fonctionnel identique aux originaux, seul le guard est ajoute.
