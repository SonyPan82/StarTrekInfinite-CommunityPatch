CP26 - WAR REWORK OPTIONS (2026-05-17)
======================================

Objectif
--------
Remplacer les surcouches de guerre coûteuses et fragiles par un système plus lisible,
plus stable, et moins gourmand en CPU pendant les grosses guerres.


Constat actuel
--------------
1. `war_situation` reste une très grosse machine scriptée :
   - démarrage global au début des guerres
   - beaucoup d'effets mensuels / participants / événements secondaires
   - bon candidat aux freezes et aux charges CPU en late game

2. `cp26_war_access` ajoute une logique spéciale d'ouverture de frontières :
   - utile comme rustine
   - mais c'est encore une couche custom à surveiller
   - risque de recalculs d'accès et de pathfinding

3. Le vrai coût du jeu en guerre semble venir d'un empilement :
   - logique de guerre globale
   - déplacements massifs
   - nombreuses petites flottes
   - événements/hooks de guerre


Option A - Retour quasi vanilla (recommandation stabilité)
----------------------------------------------------------
Principe :
- supprimer `war_situation` du runtime
- supprimer `cp26_war_access`
- laisser le moteur gérer guerres, accès et combats avec un minimum d'overrides

Avantages :
- solution la plus stable
- charge CPU plus prévisible
- beaucoup moins de dette script
- meilleur point de départ pour mesurer les vrais problèmes moteur/gameplay

Inconvénients :
- perte de l'habillage narratif/politique des guerres
- certaines situations Star Trek spéciales devront être refaites autrement

Usage recommandé :
- base saine pour workshop
- base saine avant toute vraie refonte guerre/crises


Option B - Guerre scriptée légère, locale, non globale
------------------------------------------------------
Principe :
- ne plus créer de `global_situation`
- remplacer par quelques événements ciblés :
  - au début de guerre
  - à la paix
  - sur quelques jalons rares (annuel, pas mensuel)
- effets limités aux vrais belligérants, pas à toute la galaxie

Avantages :
- garde un peu de saveur
- bien moins lourd qu'une situation globale
- plus facile à tester

Inconvénients :
- demande une réécriture propre
- moins “spectaculaire” que l'ancien système

Usage recommandé :
- si on veut conserver une identité CP26 sans retomber dans l'usine à gaz


Option C - Refonte guerre par théâtre / arc dédié
-------------------------------------------------
Principe :
- ne pas avoir un système universel pour toutes les guerres
- garder des scripts lourds seulement pour des arcs précis :
  - Dominion
  - Borg
  - grandes crises
- laisser les guerres ordinaires en quasi vanilla

Avantages :
- meilleur compromis perf / ambiance
- les scripts lourds sont réservés aux cas spéciaux qui le méritent
- beaucoup plus lore-friendly

Inconvénients :
- il faut distinguer clairement guerre standard vs arc spécial
- demande un peu de discipline de design

Usage recommandé :
- meilleure solution long terme si on veut du Star Trek scénarisé sans tuer les perfs


Option D - Rustines conservées mais raréfiées
---------------------------------------------
Principe :
- garder `war_situation` ou `war_access`, mais les limiter :
  - déclenchement seulement pour majors
  - pas d'observateurs tiers
  - refresh annuel au lieu de mensuel
  - événements beaucoup moins nombreux

Avantages :
- moins de réécriture immédiate
- permet de garder des systèmes déjà existants

Inconvénients :
- dette technique toujours présente
- risque de bugs/freeze toujours supérieur aux options A/B/C
- difficile à valider complètement

Usage recommandé :
- seulement comme solution temporaire


Recommandation finale
---------------------
La meilleure direction est :

1. Court terme :
   - Option A pour stabiliser le mod
   - audit réel des performances sans surcouche

2. Moyen terme :
   - Option C comme cible
   - guerres normales = vanilla / léger
   - arcs spéciaux = scripts dédiés, locaux et lore-friendly

3. À éviter :
   - remettre un système global mensuel type `war_situation`
   - réintroduire un `war_access` qui rescane toute la galaxie régulièrement


Résumé simple
-------------
Le système de guerre le plus sain pour CP26 n'est pas une grosse couche universelle.
Le plus robuste est :

- guerre standard = moteur vanilla
- arcs narratifs spéciaux = scripts locaux et exceptionnels
- pas de boucle mensuelle globale si on peut l'éviter
