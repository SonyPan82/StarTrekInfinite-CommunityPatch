CP26 Colony Spawn Audit Summary - 2026-05-21
============================================

Audit target
------------
Verify colony-spawn ownership logic across the custom empire setup layer and
special static systems.


What was checked
----------------
1. Scripted colony creation effects in:
   - common/scripted_effects/
2. Static and custom empire system initializers in:
   - common/solar_system_initializers/
3. Start events and on_actions that post-process ownership after galaxy setup.


Key result
----------
Only three dedicated colony scripted effects were found in active use:

1. create_glintara_colony
2. create_rura_penthe_colony
3. create_ferenginar_colony

Assessment:
- `create_glintara_colony` was already robust because it uses
  `event_target:romulan_country`.
- `create_rura_penthe_colony` was fragile because it used `set_owner = ROOT`.
- `create_ferenginar_colony` was fragile because it used `set_owner = ROOT`.


Repairs applied
---------------
- `create_rura_penthe_colony` now prefers `event_target:klingon_country`
- `create_ferenginar_colony` now prefers `event_target:ferengi_country`
- both fall back to ROOT only if the event target is unavailable

- The relevant initializers were aligned with the working Romulan pattern by
  explicitly assigning owner before applying colony effects:
  - klingon/cp26_beta_penthe_initializer.txt
  - aa_ferengi_initializer.txt


Broader spawn risk found
------------------------
Even where colony effects were fine, many outpost systems still relied on
event-target timing for starbase ownership.

That does not always break, but it is a common source of:
- wrong outpost owner
- missing special colony
- systems drifting into the wrong empire

To cover this, a start-of-game repair event was added:
- events/zz_cp26_spawn_repair_events.txt

Hook:
- common/on_actions/zz_cp26_on_game_start.txt


Conclusion
----------
The colony-spawn layer is now materially safer.

The main problems identified in this audit were:
- wrong scope assumptions (`ROOT`) inside colony scripted effects
- and post-setup ownership drift on tagged outpost systems

Those two issues are now explicitly handled.
