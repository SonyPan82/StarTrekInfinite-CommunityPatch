CP26 - Rura Penthe Game Start Rewire
Date: 2026-05-21

Problem
- Rura Penthe behaved differently from Sol Nova and Denobula.
- Sol Nova is a fixed scenario system with a direct outpost initializer.
- Denobula gets its owner/colony state from a proper global startup path.
- Rura Penthe still relied on Klingon-specific startup events and repair passes, which made it depend on who the player selected.

Fix
- Rewired Rura Penthe colony ownership/setup into:
  - events/game_start.txt -> game_start.1
- Added a global capture pass for:
  - ufop_country
  - klingon_country
  - romulan_country
  - cardassian_country
- Replaced the old Rura Penthe block (deposit + modifier only) with a full colony setup block:
  - if not already a colony -> create_rura_penthe_colony = yes
  - else -> force owner to Klingon Empire and set colony type
  - always reapply deposit/modifier
  - always force the system outpost to Klingon ownership

Why this is the correct layer
- `game_start.1` is the global startup event that runs when the galaxy and countries are fully assembled.
- This matches the successful pattern used by other CP26 bespoke systems more closely than country-specific start events.
- It removes the dependency on the player selecting the Klingons.

Expected result
- Rura Penthe should now spawn as a Klingon colony no matter which empire the player starts with.
