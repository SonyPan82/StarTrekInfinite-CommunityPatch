CP26 FERENGI V2 - CONSTRUCTOR AND PLATFORM LIMITS
Date: 2026-05-22

Summary
- Ferengi orbital branches were converted into proper megastructure-style definitions.
- The Ferengi planet button and Ferengi edict now act as an overview/dashboard only.
- Placement limits were formalized:
  - maximum 3 Ferengi platforms per host empire
  - maximum 1 Ferengi platform per host system
- Ferengi orbital platforms now use Ferengi citadel visuals instead of the generic habitat entity.

Technical changes
- File: common/megastructures/cp26_ferengi_branch_hubs.txt
  - Added construction_entity, build_time, and build cost fields.
  - Switched entity to ferengi_starbase_citadel_entity.
  - Switched construction_entity to ferengi_starbase_citadel_construction_entity.
  - Added commercial-pact based possible trigger on foreign host systems.
  - Added planet placement validation:
    - colony only
    - upgraded capital required
    - no existing Ferengi branch modifier on target colony
    - 1 platform max per system
    - 3 platforms max per host empire
    - one instance of each branch type per host empire through relation-flag gating
  - on_build_complete now applies the planet modifier and relation flags, and sends host notification.

- File: common/button_effects/cp26_button_effects.txt
  - Ferengi planet button now opens the platform overview only.
  - No direct build flow is opened from foreign planets anymore.

- File: common/edicts/cp26_ferengi_branch_edict.txt
  - Edict now opens the overview/dashboard only.

- File: events/cp26_ferengi_branch_events.txt
  - Removed the overview link back into the old direct branch-construction event flow.
  - AI target selection now respects:
    - max 3 host platforms
    - max 1 platform per system
  - AI branch choice now fills missing host platform types in sequence rather than treating the host as "one and done".

Notes
- Player-facing construction is now meant to ride on the vanilla megastructure/construction-ship flow.
- AI still uses the scripted backend to instantiate its platforms; this keeps the system reliable without depending on ship-order UI for AI.
