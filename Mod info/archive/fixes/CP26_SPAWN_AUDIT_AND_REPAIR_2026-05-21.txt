CP26 Spawn Audit and Repair - 2026-05-21
========================================

Scope
-----
Audit and stabilization pass on start-of-game empire/system ownership logic,
focused on:

- Klingon Rura Penthe
- Federation outpost ownership (example: Korvat)
- Ferengi capital robustness
- General fragility in special-system spawn logic


Findings
--------

1. Mixed spawn models were in use
---------------------------------
Some systems relied on robust initializers with explicit owner event targets.
Others relied on start events that re-applied ownership later.

Example:
- Rura Penthe had both:
  - an initializer-based spawn path
  - and a separate `cp26_setlik.3` country event

This duplication increases the chance of race conditions and partial setup.


2. Two colony scripted effects were using `set_owner = ROOT`
------------------------------------------------------------
This is safe only when the scripted effect is called from a country event where
ROOT is the owning country.

It is fragile when the same effect is called from an initializer's
`late_init_effect`, because ROOT may not be the empire scope expected.

Affected files:
- common/scripted_effects/cp26_rura_penthe_effects.txt
- common/scripted_effects/cp26_ferengi_colony_effects.txt

Fix:
- Both now prefer explicit event targets if available:
  - `event_target:klingon_country`
  - `event_target:ferengi_country`
- They fall back to ROOT only if the event target is unavailable.


3. Initializer consistency gap
------------------------------
Working static colonies such as Romulan Glintara explicitly set owner before
running their colony scripted effect.

Rura Penthe and the first Ferengi capital initializer path did not.

Fix:
- `common/solar_system_initializers/klingon/cp26_beta_penthe_initializer.txt`
  now explicitly assigns Klingon ownership before applying the colony effect.
- `common/solar_system_initializers/aa_ferengi_initializer.txt`
  now explicitly assigns Ferengi ownership before applying the colony effect in
  the initializer path.


4. Special outpost ownership remained vulnerable to bad timing
--------------------------------------------------------------
Systems such as Korvat are placed as static systems using faction-tagged
initializers (`ufop_system`, `klingon_system`, etc.).

Even when the map data is correct, late ownership can still drift if:
- the expected event target is not ready
- or a special event reassigns ownership inconsistently

Fix:
- Added a one-time repair event:
  `events/zz_cp26_spawn_repair_events.txt`
- Hooked into:
  `common/on_actions/zz_cp26_on_game_start.txt`

Behavior:
- UFOP: repairs all `outpost + ufop_system` starbases
- Klingon: repairs all `outpost + klingon_system` starbases and ensures
  Rura Penthe exists and belongs to the Klingons
- Romulan: repairs all `outpost + romulan_system` starbases
- Cardassian: repairs all `outpost + cardassian_system` starbases
- Ferengi: repairs Ferengi home system ownership/starbase


Files changed
-------------
- common/scripted_effects/cp26_rura_penthe_effects.txt
- common/scripted_effects/cp26_ferengi_colony_effects.txt
- common/solar_system_initializers/klingon/cp26_beta_penthe_initializer.txt
- common/solar_system_initializers/aa_ferengi_initializer.txt
- events/zz_cp26_spawn_repair_events.txt
- common/on_actions/zz_cp26_on_game_start.txt


Practical conclusion
--------------------
The biggest structural weakness was not a single empire, but the combination of:

- initializer-based ownership
- event-based post-processing
- and scripted effects that assumed the wrong ROOT scope

This patch is meant to make the start map deterministic again without changing
the intended geography.
