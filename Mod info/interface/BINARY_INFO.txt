BINARY INFO - Infinite / CP26
============================

Fichier cree le 2026-05-20.

Objet
-----

Ce fichier recense ce qui est visible dans le binaire principal du jeu Infinite, pas
seulement l'interface.

Binaire analyse:

/Library/Application Support/Steam/steamapps/common/Infinite/infinite.app/Contents/MacOS/infinite

Attention: ce document est une cartographie de reverse engineering statique. Il ne modifie
rien. Les adresses notees sont les adresses virtuelles Mach-O vues par nm/otool pour cette
build precise.


1. Resume tres court
--------------------

Le binaire principal est un executable Mach-O 64-bit x86_64, fortement symbolise.
Il contient beaucoup de noms C++ exploitables:

- environ 190 948 symboles nm au total
- environ 77 120 symboles globaux
- environ 244 591 chaines strings
- liaison avec libc++.1.dylib
- SDL/Cocoa/OpenGL/CoreAudio integres/utilises
- libcurl, bzip2, FreeImage, FreeType, Steam, POPS/Paradox visibles
- moteur de scripting Paradox visible: triggers, effects, scripted lists, databases
- tres grand nombre de commandes gameplay reseau/simulation visibles
- GUI fortement visible: CGuiObject, CFixedWindow, CContainerWindow, TButton, views

Conclusion pratique:

Le binaire est assez parlant pour une analyse avancee. Pour modder, privilegier les
fichiers data quand une fonctionnalite est exposee. Pour les comportements non exposes,
les symboles donnent de bons points d'ancrage pour recherche/hooking.

19. Notes patch binaire
-----------------------

Comme le jeu ne devrait plus recevoir de mises a jour, les adresses de cette build sont
beaucoup plus stables qu'un jeu encore maintenu. Malgre ca:

- toujours garder infinite original
- toujours noter les bytes originaux avant patch
- convertir adresse virtuelle vers offset fichier avant patch
- verifier la signature macOS apres patch
- preferer un hook externe ou dylib injectee si le patch grossit
- privilegier les chemins data/scripts quand ils existent

Pour un patch direct dans __TEXT:

Adresse virtuelle dans nm:

0x100000000 + offset virtuel __TEXT

Le segment __TEXT commence ici a:

vmaddr 0x100000000

Donc, pour beaucoup de fonctions dans __TEXT, l'offset relatif simple est:

offset_virtuel = adresse - 0x100000000

Mais il faut confirmer avec otool -l la correspondance fileoff/addr de la section exacte
avant d'ecrire dans le fichier.


20. Conclusion
--------------

Ce binaire est tres exploitable en lecture:

- noms C++ conserves
- symboles gameplay massifs
- commands et databases lisibles
- moteur script/trigger/effect visible
- GUI et button effects clairement presents
- services online/Steam/POPS visibles
- rendu/audio/input/localisation/save/load identifiables

Pour CP26, l'approche recommandee est:

1. chercher d'abord une solution .gui/common/events/scripted_effects
2. utiliser les commands/effects visibles pour comprendre quel systeme existe deja
3. patcher/hooker seulement si l'action voulue n'est pas exposee aux fichiers data
4. documenter chaque adresse et chaque patch dans ce fichier ou un fichier dedie
