HOW TO - Ajouter un bouton cable a l'interface CP26
===================================================

Objectif
--------

Ce guide explique comment ajouter un bouton dans un fichier .gui et le relier a un effet
scriptable sans patcher le binaire du jeu.

La piste la plus stable trouvee dans le binaire est le systeme natif:

- effectbuttonType dans les fichiers interface/*.gui
- common/button_effects/*.txt pour definir l'action executee
- CEffectButton::ExecuteEffect() cote moteur

En clair: le moteur sait deja creer un bouton d'interface qui appelle un effet defini en
data. Il faut donc l'utiliser avant d'envisager un patch Mach-O.


1. Structure a creer dans le mod
--------------------------------

Depuis la racine du mod CP26, la structure ideale est:

CP26/
  common/
    button_effects/
      cp26_button_effects.txt
  interface/
    fichier_a_modifier.gui

Le dossier interface existe deja. Si common/button_effects n'existe pas encore, il faut le
creer.


2. Ajouter le bouton dans un fichier .gui
-----------------------------------------

Dans le fichier .gui de l'ecran cible, ajouter un bloc effectbuttonType a l'interieur du
windowType/container concerne.

Exemple minimal:

effectbuttonType = {
    name = "cp26_test_button"
    quadTextureSprite = "GFX_fleetview_destroy_fleet"
    position = { x = 283 y = 0 }
    scale = 1
    orientation = UPPER_LEFT
    effect = "cp26_test_button_effect"
    clicksound = "confirmation"
}

Champs importants:

name
    Nom de l'objet GUI. Il doit etre unique dans la fenetre.

quadTextureSprite
    Sprite affiche sur le bouton. Reutiliser un GFX_* existant au debut, puis remplacer
    par un sprite CP26 si besoin.

position
    Position du bouton dans son parent.

orientation
    Point d'ancrage. UPPER_LEFT est le plus simple pour tester.

effect
    Nom de l'effet defini dans common/button_effects/*.txt.

clicksound
    Son joue au clic. Optionnel, mais utile pour confirmer que le clic est bien recu.


3. Definir l'effet dans common/button_effects
---------------------------------------------

Creer ou completer:

common/button_effects/cp26_button_effects.txt

Exemple de test volontairement inoffensif:

cp26_test_button_effect = {
    potential = {
        always = yes
    }

    allow = {
        always = yes
    }

    effect = {
        add_monthly_resource_mult = {
            resource = minerals
            value = 5
            min = 5
            max = 500
        }
    }
}

potential
    Condition d'affichage/activation generale. Pour un premier test: always = yes.

allow
    Condition qui autorise le clic. Pour un premier test: always = yes.

effect
    Action executee au clic.


4. Attention aux scopes
-----------------------

Le fichier vanilla indique que les scopes changent selon ce qui est selectionne:

This
    Objet selectionne si applicable: planete, vaisseau, flotte, systeme, megastructure,
    federation, operation espionnage, site archeologique, first contact, etc.
    Sinon, le pays du joueur.

From
    Pays du joueur.

Conseil important:

Toujours verifier le type de scope dans allow ou effect si l'effet depend d'un objet.

Exemple:

cp26_planet_only_button_effect = {
    potential = {
        is_scope_type = planet
    }

    allow = {
        is_scope_type = planet
    }

    effect = {
        add_deposit = d_minerals_3
    }
}

Sans verification, un bouton ouvert pendant qu'une flotte ou un pays est selectionne peut
envoyer l'effet au mauvais scope.


5. Tester rapidement
--------------------

Etapes conseillees:

1. Ajouter le bouton avec always = yes dans potential et allow.
2. Lancer le jeu avec le mod CP26.
3. Ouvrir l'ecran modifie.
4. Verifier que le bouton apparait.
5. Cliquer et verifier le son/l'effet.
6. Recharger l'interface si la console le permet:

reloadgui

Il existe aussi une fonction dans le binaire:

OnExecute_ReloadGUI(CArray<CString> const&)

Donc la commande console reloadgui est probablement le chemin normal si elle est exposee
dans cette build.


6. Debug visuel
---------------

Le binaire contient aussi:

OnExecute_GuiBounds(CArray<CString> const&)

Si une commande console equivalente existe, elle peut aider a afficher les bounds GUI.
Sinon, debug a l'ancienne:

- mettre le bouton tres visible
- utiliser un sprite connu
- positionner d'abord en x=0 y=0
- agrandir temporairement la zone parent
- verifier le clipping=yes des parents


7. Fonctions moteur reperees dans le binaire
--------------------------------------------

Ces symboles confirment le fonctionnement general du cablage GUI:

CEffectButton::ExecuteEffect()
CEffectButton::UpdateAllInstances()
CButtonEffect::ReadMember(CReader&, int)
CCommandHelper<CExecuteButtonEffectCommand>

CGuiObject::SetAcceptClicks(bool)
CGuiObject::SetAcceptRightClicks(bool)
CGuiObject::ProcessInput(CInputEvent&, CMouse*)

CFixedWindow::CreateButton(CString const&, CString const&)
CFixedWindow::GetSubWindow(CString const&)
CFixedWindow::GetFixedWindow(CString const&)
CFixedWindow::SetButtonFilterOnAll(IButtonEventFilter*)

CContainerWindow::CreateButton(CString const&, CString const&)
CContainerWindow::SetButtonFilterOnAll(IButtonEventFilter*)

CButtonObjectGlue<...>::OnClick(CGuiObject*)
CButtonObjectGlue<...>::OnRightClick(CGuiObject*)
CButtonObjectGlue<...>::OnOver(CGuiObject*)
CButtonObjectGlue<...>::OnLeave(CGuiObject*)

Ces fonctions sont utiles pour comprendre le moteur, mais il vaut mieux eviter de patcher
directement le binaire tant que effectbuttonType suffit.


8. Exemple complet a copier
---------------------------

Dans interface/mon_ecran.gui:

effectbuttonType = {
    name = "cp26_open_debug_button"
    quadTextureSprite = "GFX_fleetview_destroy_fleet"
    position = { x = 20 y = 20 }
    scale = 1
    orientation = UPPER_LEFT
    effect = "cp26_open_debug_button_effect"
    clicksound = "confirmation"
}

Dans common/button_effects/cp26_button_effects.txt:

cp26_open_debug_button_effect = {
    potential = {
        always = yes
    }

    allow = {
        always = yes
    }

    effect = {
        custom_tooltip = "cp26_debug_button_clicked"
    }
}

Puis ajouter la localisation si le tooltip doit etre affiche:

localisation/english/cp26_l_english.yml

l_english:
 cp26_debug_button_clicked:0 "CP26 debug button clicked."


9. Checklist avant commit
-------------------------

[ ] Le bouton a un name unique.
[ ] Le sprite GFX_* existe.
[ ] L'effet reference dans effect = existe dans common/button_effects.
[ ] potential et allow sont assez restrictifs pour eviter les mauvais scopes.
[ ] Le bouton n'est pas coupe par clipping=yes.
[ ] Le bouton ne recouvre pas un autre bouton important.
[ ] Le test a ete fait en jeu apres reloadgui ou relance.


10. Quand envisager le binaire
------------------------------

Patch binaire ou hooking seulement si:

- l'action voulue n'existe pas en script effect
- il faut intercepter un clic sur un bouton vanilla deja cable en C++
- il faut appeler une methode C++ specifique non exposee aux scripts
- il faut ajouter un nouveau type d'objet GUI que le parser .gui ne sait pas creer

Pour tout le reste, preferer:

interface/*.gui + common/button_effects/*.txt

Ce sera plus maintenable, plus facile a tester, et beaucoup moins fragile entre versions.
