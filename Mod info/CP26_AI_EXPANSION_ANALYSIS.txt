RESUME EXECUTIF
---------------
Les empires IA (vanilla majors Klingon/Romulan/Cardassian et CP26 minors 
Breen/Gorn/Orion/Tholian) ne colonisent ni n'etendent pas leurs frontieres,
alors que l'UFOP (joueur ou IA) semble le faire.

Cela est du a 5 facteurs qui se renforcent mutuellement, plus une particularite
de la carte CP26 (primitive_odds = 1.0).

================================================================================
1. SEUIL D'INFLUENCE TROP ELEVE POUR LES OUTPOSTS
================================================================================

Fichier source (vanilla, non override par CP26) :
  common/ai_budget/00_alloys_budget.txt

Bloc bloquant :
  alloys_expenditure_starbases_expand = {
      potential = {
          has_ai_expansion_plan = yes
          highest_threat < 50
          has_resource = { type = influence amount > 75 }   <-- BLOQUE
      }
      ...
  }

Analyse :
  - Les majors (country_type = default) ont influence = 3/mois de base.
  - Les minors (country_type = contender) ont aussi influence = 3/mois.
  - Il faut 75 / 3 = 25 mois (2 ans) pour atteindre le seuil.
  - L'IA n'alloue AUCUN budget alloys a l'expansion tant que ce seuil n'est
    pas atteint. Resultat : aucun outpost n'est construit pendant longtemps.

Seuls Romulan et Cardassian ont des bonus ponctuels :
  - Romulan : civic_closet_politics (+0.25) + job imperial_kin_romulan (3x0.1)
            = ~0.55 influence/mois supplementaire.
  - Cardassian : event first contact hostile (action.1.c) = +100 influence
               (une seule fois).

================================================================================
2. SEUIL DE NOURRITURE TROP ELEVE POUR LES COLONY SHIPS
================================================================================

Fichier source (vanilla, non override par CP26) :
  common/ai_budget/00_food_budget.txt

Bloc bloquant :
  food_expenditure_colonies_expand = {
      potential = {
          ai_colonize_plans > 0
          has_resource = { type = food amount > 2000 }      <-- BLOQUE
          has_monthly_income = { resource = food value > 0 }
          is_at_war = no
      }
      ...
  }

Analyse :
  - Le colony ship standard coute food = 2000 (voir point 3).
  - L'IA n'alloue du budget food a la colonisation que si elle a > 2000 en
    stock. Aucun major ne demarre avec autant :
      UFOP      : food = 500
      Klingon   : food = 200
      Romulan   : food = 700
      Cardassian: food = 100
  - Meme avec la production mensuelle des districts farming, il faut de
    nombreux mois pour atteindre 2000.

================================================================================
3. COUT DU COLONY SHIP ET SHIP_DATA BLOQUANT
================================================================================

Fichier source (vanilla, non override par CP26) :
  common/ship_sizes/00_ship_sizes.txt

Cout du colonizer standard :
  colonizer = {
      resources = {
          cost = {
              trigger = { from = { is_lithoid_empire = no is_hive_empire = no } }
              alloys = 150
              food   = 2000            <-- COUT PROHIBITIF
          }
      }
  }

Ship data dans country_types (vanilla) :
  common/country_types/00_country_types.txt

  default (majors) :
      colonizer = {
          modifier = {
              resource_stockpile_compare = { resource = food value < 2000 }
              factor = 0               <-- IA ne veut pas construire
          }
      }

  contender (minors CP26) :
      colonizer = {
          modifier = {
              OR = {
                  resource_stockpile_compare = { resource = food   value < 250 }
                  resource_stockpile_compare = { resource = energy value < 500 }
              }
              factor = 0               <-- IA ne veut jamais construire
          }
      }

Analyse :
  - Pour les majors, l'IA desactive completement la construction de colonizers
    tant qu'elle a moins de 2000 food.
  - Pour les minors, avec food = 20 et energy = 35 de base, ils ne pourront
    JAMAIS atteindre les seuils (250 et 500).

================================================================================
4. PRIMITIVE_ODDS = 1.0 — AUCUNE PLANETE COLONISABLE
================================================================================

Fichier source (CP26) :
  map/setup_scenarios/Alpha-Beta_medium.txt
  map/setup_scenarios/tutorial.txt

Parametres :
  primitive_odds = 1.0          <-- 100% des planetes habitables ont des primitifs
  colonizable_planet_odds = 0.5 <-- Seulement 50% des systemes ont une planete habitable

Analyse :
  - Dans Stellaris, l'AI est reticente a coloniser les mondes avec des
    civilisations primitives.
  - Avec primitive_odds = 1.0, PRESQUE TOUTES les planetes colonisables sont
    des mondes primitifs. L'IA considere qu'il n'y a aucune cible valide.
  - Meme si le joueur humain peut forcer la colonisation, l'AI refuse.

================================================================================
5. AUCUN SHIPYARD AU DEPART
================================================================================

Fichiers source (CP26) :
  common/solar_system_initializers/ufop/*.txt
  common/solar_system_initializers/klingon/*.txt
  common/solar_system_initializers/romulan/*.txt
  common/solar_system_initializers/cardassian/*.txt

Observation :
  - TOUS les systemes de demarrage (capitales + systemes conquis) utilisent :
      create_starbase = { size = starbase_outpost }
  - Le vanilla hornblower_initializers.txt utilisait starbase_starport pour les
    capitales, mais CP26 a supprime ces late_init_effect dans ses override.

Analyse :
  - starbase_outpost ne peut PAS construire de vaisseaux (pas de module shipyard).
  - L'IA doit d'abord upgrader sa capitale en starbase_starport (cout : 200 alloys).
  - Cela retarde encore d'autant mois la possibilite de construire quoi que ce soit.

================================================================================
POURQUOI L'UFOP SEMBLE EXPANDRE
================================================================================

1. COLONIES DE DEPART PAR EVENT
   UFOP a 13 systemes dans conquered_system_initializers, dont plusieurs avec
   des colonies pre-creees par scripted effects :
     - create_andor_colony
     - create_vulcan_colony
     - create_tellar_colony
     - create_deneva_colony (eventuellement)
   Ces colonies ne sont PAS construites par l'IA — elles sont spawn par le
   moteur au lancement. L'utilisateur les voit et pense a de l'expansion.

2. JOUEUR HUMAIN
   Si l'utilisateur joue UFOP, il peut contourner toutes les restrictions de
   l'IA (construire manuellement, coloniser des mondes primitifs, etc.).

3. AUTRES MAJORS AUSSI DES COLONIES DE DEPART
   Klingon, Romulan et Cardassian ont aussi des colonies de depart via leurs
   conquered_system_initializers (Boreth, Chaltok, Amleth, etc.).
   La difference est que UFOP en a PLUS et qu'elles sont plus visibles.

================================================================================
CE QUE CP26 A DEJA CORRIGE (ne pas modifier)
================================================================================

1. WAR_PHILOSOPHY POUR CONTENDERS
   CP26/common/policies/00_policies.txt :
      potential = {
          or = {
              is_country_type = default
              is_country_type = contender          <-- AJOUTE PAR CP26
          }
      }
   Les minors peuvent maintenant choisir unrestricted_wars.

2. CAN_ADD_CLAIM POUR CONTENDERS
   CP26/common/game_rules/00_rules.txt :
      hidden_trigger = {
          if = {
              limit = {
                  root = {
                      NOT = { is_country_type = default }
                      NOT = { is_country_type = contender }   <-- CP26 a ajoute contender
                  }
              }
              always = yes
          }
      }
   Les contenders passent le hidden_trigger et peuvent faire des claims
   s'ils ont unrestricted_wars.
